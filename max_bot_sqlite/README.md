# YAMAL MAX Bot (SQLite)

Бот работает без SeaTable, только на локальной SQLite базе, собранной из папки с файлами.

Новый production-каталог выкатывается release-архивом `new-yamal-catalog.tar.gz` через workflow `Deploy New Yamal Catalog To BOTSGSN`.

На той же базе теперь можно поднять отдельный сайт:
- [README сайта](/root/projects/yamal_brand/yamal_catalog_site/README.md)
- [README сайта для shared hosting](/root/projects/yamal_brand/yamal_catalog_site_php/README.md)

Что уже настроено в боте:
- стартовый экран и главное меню используют согласованный onboarding-текст про официальный каталог бренда Ямала для государственных служащих и предпринимателей
- главное меню собрано в фиксированном порядке: `Как пользоваться`, `Поиск`, `Мастер-бренд Ямала`, `Ямал-100`, `Фирменные стили МО`, `Избранное`
- отдельная кнопка `⭐ Избранное` с часто открываемыми файлами и разделами
- второй уровень кнопок с короткими названиями для логотипов, паттернов и сувенирных категорий без отдельных верхних кнопок городских брендбуков
- третий уровень с компактными рядами кнопок для цветовых вариантов и форматов файлов
- перед каждым новым ответом бот удаляет свой предыдущий ответ в чате
- текстовый поиск с учетом опечаток, синонимов, бытовых формулировок и транслитерации
- бот пишет runtime-аналитику в отдельную SQLite базу `max_bot_runtime.db`
- бот считает уникальных пользователей, новые/активные аудитории за последние 7 дней и общее число взаимодействий для админ-отчета
- при запуске бот обновляет подсказки MAX-команд (`/start`, `/menu`, `/search`, `/help`, `/myid`, `/admin`) и пишет в журнал обезличенные metadata входящих update для диагностики `Start`/кнопок
- поиск как по файлам, так и по папкам
- отправка файла прямо в чат

## 1) Собрать базу из структуры папок

```bash
python3 /home/sergey/yamal_brand/scripts/build_sqlite_catalog.py \
  --source "/home/sergey/yamal_brand/input/Макеты1" \
  --db "/home/sergey/yamal_brand/max_catalog.db"
```

## 2) Установить зависимости

```bash
cd /home/sergey/yamal_brand/max_bot_sqlite
cp .env.example .env
npm install
```

Для автодеплоя отдельная системная установка Node.js не обязательна: deploy-скрипт сам скачает локальный runtime в `/home/sergey/yamal_brand/.runtime/node`.
Основной режим запуска: `systemd`-сервис `max_yamal_bot.service`.
Deploy-скрипт теперь требует passwordless `sudo` для `cp`, `systemctl` и `journalctl`, чтобы бот всегда запускался как нормальный сервис, а не как фоновый user-process.

Заполни в `.env`:
- `MAX_BOT_TOKEN`
- `RUNTIME_DB_PATH` при необходимости, если runtime-аналитику нужно хранить не рядом с каталогом
- `FAVORITES_LIMIT` если нужно больше или меньше элементов в разделе `Избранное`
- при необходимости `ALLOWED_USER_IDS`
- `ADMIN_USER_IDS` для пользователей, которым доступен `/admin` и `/stats`; текущий админский ID: `23325864`; если переменная пустая, бот использует `ALLOWED_USER_IDS` как fallback только для закрытого контура

Относительные пути в `.env` (`CATALOG_DB_PATH`, `RUNTIME_DB_PATH`, `CATALOG_ROOT_PATH`) считаются от папки `max_bot_sqlite`. При старте бот до открытия SQLite проверяет, что база каталога существует, runtime-папка доступна, а корневая папка каталога есть на диске. Если каталог еще не собран, ошибка укажет `npm run build-db`.

## Что умеет бот

- на `/start`, системный `Start`, `/menu` и возврат в корень через кнопку `Меню` бот показывает один и тот же согласованный onboarding-текст без сокращённой версии
- простое открытие уже существующего чата без `Start`, `/start` или первого сообщения не даёт отдельного update в текущем MAX API-контуре, поэтому бот не может сам показать приветствие просто по факту открытия окна
- на старте процесса команды публикуются через MAX API, чтобы клиент видел штатные подсказки команд
- `/start` и `/menu`: полное меню по основным разделам каталога
- нажатие системной кнопки Start в MAX обрабатывается до общего роутинга событий и тоже открывает меню; в journal это видно по строкам `[start] sending main menu` и `[start] main menu sent`
- `/search <запрос>` или просто текст: умный поиск по файлам и папкам
- `/myid`: показать ваш `sender_id` и `chat_id` прямо в чате
- отдельная кнопка `Поиск` открывает экран с подсказкой и быстрыми поисковыми кнопками
- отдельная кнопка `Избранное` показывает популярные разделы и файлы, а пока статистики мало - базовые стартовые разделы
- `/admin` и `/stats`: закрытый админ-отчет по runtime-аналитике
- в разделе `Как пользоваться` есть кнопки `Назад` и `Меню`, а сам текст объясняет главный экран, поиск, избранное и текстовые запросы на конкретных примерах
- при новом действии бот удаляет свой предыдущий ответ, чтобы не копить старые сообщения
- клавиатура адаптируется под размер экрана: длинные кнопки идут по одной, средние по две, короткие до трех в ряд
- отправка сообщений и файлов в MAX API теперь идет с retry/backoff на краткие сетевые таймауты и `Attachment not ready`
- поиск стал терпимее к опечаткам, близким словам и неверной раскладке клавиатуры
- поиск и build-индекс знают больше бытовых слов: `наклейка`, `стикер`, `одежда`, `худи`, `полиграфия`, `диджитал`, `презентация`, `канцелярия`
- по кнопке папки: открытие раздела с короткими и понятными названиями подпапок
- по кнопке файла: отправка файла напрямую

## Как теперь выглядит навигация

- верхний уровень идёт в порядке: `Как пользоваться` -> `Поиск` -> `Мастер-бренд Ямала` -> `Ямал-100` -> `Фирменные стили МО` -> `Избранное`
- вложенные кнопки повторяют структуру нового каталога: брендбук, логотипы, шрифты, паттерны, иллюстрации, муниципалитеты и форматы файлов
- если имя файла или папки начинается со знаков вроде запятой, точки или тире, бот убирает этот мусор и начинает кнопку со слова с заглавной буквы
- длинные файловые кнопки сокращаются логично: повтор папки убирается, а формат переносится в конец, например `Белые • PDF`
- из файловых кнопок убираются малополезные слова вроде `макет`, `версия`, `финальный`, `для печати`, если без них смысл остается понятным
- у брендбуков прямой PDF показывается раньше папки `Файлы и исходники`
- в папках `CMYK / Color / Black / White` файлы показываются как короткие кнопки форматов: `AI`, `CDR`, `EPS`, `PDF`, `PNG`, `JPG`, `SVG`
- стрелки пагинации и кнопки `Назад / Меню` выводятся отдельными рядами, чтобы навигация не сжималась на телефоне

## Поиск

Поиск использует:
- нормализацию текста (`ё/е`, регистр, спецсимволы)
- рус/лат транслитерацию
- исправление неверной раскладки клавиатуры (`kjujnbg` -> `логотип`)
- расширенные синонимы и бытовые названия (`logo/логотип/знак`, `brandbook/брендбук/гайд`, `font/шрифт/гарнитура`, `сувенир/мерч/сувенирка`)
- fuzzy ранжирование для опечаток и похожих слов
- в экране `Поиск` доступны быстрые варианты: `Логотип`, `Брендбук`, `Паттерн`, `Шрифт`, `Иллюстрация`
- если совпадений совсем нет, бот показывает экран `Пупупу....пусто` и кнопку `Меню`

## Аналитика и backup

Бот хранит runtime-события отдельно от каталога:
- `max_catalog.db` - структура файлов и папок
- `max_bot_runtime.db` - уникальные пользователи, поисковые запросы, пустые запросы, популярные файлы и разделы

Быстрый отчет по использованию:

```bash
cd /home/sergey/yamal_brand/max_bot_sqlite
npm run report-usage
```

Что попадает в weekly-отчет:
- новые пользователи за последние 7 дней
- активные пользователи за последние 7 дней
- общее число пользователей за все время
- общее число взаимодействий с ботом за все время
- общее число скачиваний файлов за все время (`send_file`)
- самые частые поиски и самые часто открываемые разделы/файлы
- для `PNG`, `JPG/JPEG` и `PDF` первый клик по файлу открывает предпросмотр с кнопкой `Скачать`; событие скачивания (`send_file`) пишется только после отправки исходного файла
- при входе в папку-вариант, где лежат форматы одного материала (`Black`, `White`, `Color` и т.п.), бот показывает предпросмотр по лучшему `PNG/JPG/PDF` на первой странице, а ниже оставляет кнопки форматов

Закрытый отчет внутри бота:
- команда `/admin`
- команда `/stats`
- внутри отчета есть переключение между `7 дней` и `Весь период`
- после успешной команды от администратора кнопки отчета остаются доступными в этом чате, чтобы MAX callback-клики работали даже без пользовательского `sender_id`

Быстро узнать свой ID прямо в боте:
- отправьте команду `/myid`
- бот ответит `sender_id` и `chat_id`

Создать резервную копию и экспорт CSV/JSON:

```bash
cd /home/sergey/yamal_brand/max_bot_sqlite
npm run backup-data
```

Будет создана timestamp-папка в `../backups/` с файлами:
- `max_catalog.db`
- `max_bot_runtime.db`
- `assets.csv`
- `top_searches.csv`
- `top_empty_searches.csv`
- `top_items.csv`
- `summary.json`

## Диагностика

```bash
cd /home/sergey/yamal_brand
LOOKBACK_HOURS=12 JOURNAL_LINES=120 ./scripts/diagnose_bot_service.sh max_yamal_bot.service
```

В журнале строки `[update]` содержат только технические поля (`updateType`, `senderId`, `chatId`, наличие текста или callback payload) без текста сообщений и без токена.
Диагностика также проверяет пути из `.env` без вывода токена и показывает `catalog_db=missing`, `runtime_dir=missing` или `catalog_root=missing`, если бот не может стартовать из-за неверного пути.
