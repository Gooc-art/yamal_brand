# PRD

## Продукт

Веб-сервис бренд-материалов Ямала на PHP + SQLite для shared hosting.

## Основные сценарии

1. Найти раздел или файл каталога.
2. Открыть карточку материала, просмотреть и скачать файл.
3. Получить grounded-консультацию по брендбуку и следующему шагу.
4. Собрать типовой носитель через `Лабораторию решений`.

## Лаборатория решений

Цель:
- ускорить выпуск типовых бренд-носителей без запуска отдельного графического продукта

MVP:
- формы для заполнения данных по носителю
- группировка полей и простой пошаговый UX внутри конструктора
- фильтры по категориям носителей на первом экране лаборатории
- генерация стартового SVG/brief-пакета
- углубленные handoff-сценарии для отдельных носителей:
  табличка с типом, номером и стрелкой; презентация со сценарием, тезисом и структурой слайдов
- единый слой оформления по всем шаблонам:
  цветовые варианты `CMYK / Color / Black / White`, выбор `логотип с надписью / фирменный знак`, управляемые фоновые элементы и явные подписи сервисных блоков
- grounded-палитра фона внутри конструктора:
  светлый, песочный, фирменный красный, северная бирюза, тёплая охра и тёмный графит с автоматическим переходом логотипа/знака в белую версию на плотных фонах
- композиция шаблона может перестраиваться от выбранных элементов:
  знак должен давать другой визуальный каркас, чем логотип с надписью
- style-режимы в форме должны показываться не обычными select, а визуальными карточками выбора; смена таких режимов должна сразу обновлять превью
- типографика этих карточек выбора должна оставаться аккуратной: длинные названия и пояснения не должны вылезать или накладываться внутри плашек, а палитра не должна тащить длинный текст внутрь цветового swatch
- у каждого носителя должны быть короткие grounded-пресеты сценариев, которые одной кнопкой переключают типовой режим `официальный / печать / контраст / навигация / питч`
- после сборки результат должен делиться на два grounded handoff-пакета:
  `на согласование` и `подрядчику`, чтобы preview/brief и production-исходники не смешивались
- рядом с превью должен быть явный индикатор заполнения шаблона: сколько полей уже заполнено и хватает ли обязательных значений
- адаптивная типографика SVG-превью, чтобы текст оставался в пределах полей и не ломал макет на длинных значениях
- единый fitter по всем шаблонам, который предпочитает полный текст без ложной обрезки, использует защитные внутренние поля и естественные переносы для сложных строк
- адаптивный preview-shell по пропорциям носителя и нормализованные сетки действий внутри конструктора
- упрощённый верхний вход в лабораторию: карточки без вторичных форматных меток и без перегруженных filter-chips
- короткие operational-summary на карточках решений вместо длинных описаний на первом экране
- рекомендации по реальным разделам и реальным файлам каталога
- draft-состояние конструктора не должно разрастаться в три длинные колонки: для старта достаточно одного компактного grounded-блока, а полные файлы и разделы после сборки должны жить уже в handoff
- deep link на конкретное решение

Не входит в текущий MVP:
- полноценный WYSIWYG-редактор
- фоновая очередь сложного рендера
- генерация `PPTX` и сложного production-ready `PDF`
