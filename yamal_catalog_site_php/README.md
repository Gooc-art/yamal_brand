# YAMAL Catalog Site PHP

PHP + SQLite версия сайта для shared hosting, в первую очередь под REG.RU.

Что умеет:
- разделы и подпапки каталога
- поиск по SQLite базе
- карточка файла
- прямое скачивание
- минималистичный интерфейс с короткими маршрутами и рабочей структурой каталога
- главный экран без дубля названия проекта: верхняя плашка объединяет знак и подпись `Официальная библиотека фирменного стиля` и остается основным акцентом hero-блока
- hero больше не отвлекает техническими счётчиками файлов и папок, верхний экран оставлен только для навигации, поиска и примеров
- в hero добавлена листаемая галерея `Примеры внедрения бренда` с вкладками `Хорошие примеры` и `Спорные примеры`
- hero-галерея примеров вынесена в левую колонку и получила миниатюры, автолистание и крупный медиа-кадр с быстрым переключением
- встроенные бренд-ассеты из каталога `Брендбук ЯМАЛ Мастер бренд`: основной логотип и фирменный знак в SVG
- верхняя навигация теперь строится из всех корневых разделов каталога, включая шрифты, брендбуки, логотипы, города, паттерны и сувенирную продукцию
- верхняя навигация по разделам собрана как одна кнопка `Открыть разделы`, после которой раскрывается компактный перечень всех разделов каталога
- карточки `Главного меню` стали короче: заголовки берутся из реальных разделов, а подписи сведены к коротким подсказкам вроде `PDF и исходники` или `TTF, OTF, архивы`
- внутри раскрытия `Главное меню` больше не тянется длинной вертикальной сценой: на ПК это плотная сетка, на мобильном аккуратный список
- у плиток главного меню есть активное состояние после открытия раздела
- на главной добавлена `Лаборатория решений`: отдельная сетка типовых носителей, которая открывает конструктор внутри той же рабочей области без перехода в другой продукт
- в лаборатории уже есть готовые каркасы для `визитки`, `таблички`, `презентации`, `сертификата`, `бейджа`, `фирменного бланка`, `digital-карточки` и `роллапа / стенда`
- у лаборатории есть фильтры по типам носителей, поэтому на первом экране можно быстро сузить список до печати, документов, событий, digital или презентаций
- каждый конструктор остается grounded: он заполняет поля, собирает стартовый SVG/brief-пакет и рядом подтягивает только реальные разделы и реальные файлы из текущего каталога
- конструктор не пытается симулировать полноценный графический редактор: сейчас он выдает готовый стартовый пакет для handoff, а не свободное редактирование макета в браузере
- верхний экран упрощен до двух сценариев: выбрать раздел в главном меню или сразу перейти в поиск
- мобильный первый экран перестроен в более логичный порядок: сначала основной вход и поиск, затем примеры, быстрые действия и чипы поиска собраны в компактные сетки без длинной колонны
- для ПК у витрины примеров остались явные стрелки и быстрые миниатюры, чтобы переключение не зависело только от вертикального скролла
- автолистание примеров и раскрытие разделов двигают только свои внутренние ряды и больше не должны дёргать страницу вверх
- нижняя рабочая область больше не показывает отдельный root-каталог и полностью скрыта на старте: она появляется только после выбора раздела, поиска или deep link
- отдельный режим `Скрыть витрину`, который оставляет только рабочую область
- нижняя рабочая область собрана как единая сцена: центральный раздел и выезжающий инспектор файла без отдельного левого рейла
- внутри рабочей области есть компактный переключатель разделов, чтобы перескакивать между основными ветками без возврата наверх
- встроенный `Помощник` открывается отдельной плавающей кнопкой: стартовые подсказки внутри диалога ведут в реальные разделы и предлагают конкретные файлы из каталога
- помощник стал умнее: он разбирает формат файла, город, носитель и запрос на исходник, помнит предыдущий шаг диалога, отвечает на практические вопросы применения и подсказывает по брендбуку вместо слепого поиска
- поверх grounded-логики помощник теперь умеет подключать опциональный глубокий ответ через OpenAI Responses API: он отвечает свободнее, но по-прежнему опирается на реальные разделы, реальные файлы и локальный разбор контекста
- на ПК помощник теперь работает как ещё более широкое диалоговое окно с отдельной зоной переписки, а на мобильном как нижний sheet с собственной прокруткой
- верхние кнопки сценариев убраны: старт теперь идёт сразу через диалог и стартовую реплику помощника внутри окна
- переходы из ответа помощника больше не закрывают окно: можно открыть раздел, поиск или карточку файла и сразу продолжить следующий вопрос
- на ПК помощник не закрывается от обычной работы по каталогу и убирается только явно кнопкой `Закрыть` или `Esc`
- карточка файла в инспекторе показывает превью для изображений/PDF/SVG, компактные плашки формата/размера/даты, быстрые действия и отдельные смысловые блоки для раздела, оригинального имени и полного пути файла
- десктопный инспектор раскрывается шире, а список файлов использует ту же текстовую иерархию, что и открытая карточка: тип, чистый заголовок, контекст и отдельные плашки формата
- список файлов в рабочей области стал спокойнее: в карточках осталось меньше служебного шума, а акцент смещен на название, контекст и 1-2 полезные плашки
- действия в карточке файла выровнены в ровную сетку одинаковых кнопок, а скроллбар инспектора оформлен явно и больше не выглядит как лишний прозрачный элемент
- у карточки файла собственный контейнер действий без наследования от списка, поэтому кнопки `Открыть / Скопировать ссылку / Скачать / К разделу` теперь имеют одну визуальную систему
- правая полоса прокрутки инспектора скрыта визуально, чтобы в карточке не оставался мусорный вертикальный след на ПК
- десктопный инспектор получил ещё немного ширины и более плотные внутренние отступы, чтобы плашки и кнопки не упирались в правый край
- мобильная рабочая область тоже упрощена: шапка каталога компактнее, toolbar собран в короткую сетку, breadcrumbs листаются горизонтально, а действия файлов в списке не растягивают экран вниз
- нажатие маршрутов и быстрых переходов автоматически прокручивает страницу к каталогу
- состояние раздела, поиска и открытого файла сохраняется в URL, поэтому страницу можно обновлять, отправлять ссылку коллегам и использовать `Назад / Вперед` в браузере без потери контекста
- сворачиваемая рабочая область, чтобы нижний рабочий блок можно было убрать с экрана
- рабочая область по умолчанию полностью скрыта на каждом новом заходе, а при переходе в раздел, поиск или deep link появляется автоматически
- стартовый экран не запоминает между перезагрузками состояния `Скрыть витрину` и раскрытой рабочей области
- понятный экран даже если база и файлы еще не загружены
- автосборка `max_catalog.db` из `data/files/`, если база еще не создана
- автоматическое обновление CSS/JS/SVG через версионирование ассетов, чтобы браузер не держал старый кэш после деплоя

## Примеры внедрения бренда

Hero-галерея собирается автоматически из каталога:
- если в каталоге есть папка `Примеры внедрения бренда территории`, сайт берет материалы в первую очередь оттуда
- внутри нее приоритетные подпапки:
  - `Хорошие примеры`
  - `Спорные примеры`
- `Хорошие примеры`:
  - сначала ищутся изображения строго в `Примеры внедрения бренда территории/Хорошие примеры`
  - если рядом есть более общая ветка `Примеры внедрения бренда/...`, приоритет всё равно остается за папкой `...территории/...`
  - если таких папок нет, сайт берет реальные кейсы из путей вида `.../Файлы/Макеты/...`
- `Спорные примеры`:
  - сначала ищутся изображения строго в `Примеры внедрения бренда территории/Спорные примеры`
  - если рядом есть более общая ветка `Примеры внедрения бренда/...`, приоритет всё равно остается за папкой `...территории/...`
  - если такой папки нет, ищутся изображения в папках со словами `Спорные`, `Антипример`, `Обсуждение`
  - если таких папок нет, вкладка остается пустой и показывает подсказку

Поддерживаются изображения `PNG`, `JPG`, `JPEG`, `WebP`.
В самом hero-блоке можно:
- переключать вкладки `Хорошие` / `Спорные`
- листать примеры стрелками
- кликать по миниатюрам
- включать и останавливать автолистание
- листать миниатюры влево-вправо

## Структура

- `index.php` - главная страница
- `api.php` - JSON API для фронтенда
- `download.php` - скачивание файла по `id`
- `src/site_lib.php` - вся backend-логика
- `assets/` - фронтенд
- `data/` - место для баз и файлов каталога

## Лаборатория решений

Сайт теперь умеет не только показывать каталог, но и собирать типовые бренд-носители как стартовые решения.

Текущий набор решений:
- `Визитка`
- `Табличка`
- `Презентация`
- `Сертификат`
- `Бейдж`
- `Пост для соцсетей`
- `Фирменный бланк`
- `Роллап / стенд`

Как это работает:
- пользователь открывает карточку решения на главной
- в рабочей области появляются сгруппированные поля, step-by-step сценарий, превью и блок скачивания артефактов
- первое открытие конструктора теперь поднимает облегчённый draft: базовые разделы и брендбук-подсказка приходят сразу, а полный подбор файлов подтягивается уже на сборке
- открытие и сборка конструктора теперь сами принудительно раскрывают рабочую область; если backend временно не ответит, пользователь видит явный retry-state вместо пустого экрана
- на ПК превью-панель закреплена справа, чтобы результат и файлы не терялись при прокрутке длинной формы
- форму можно быстро вернуть к базовому шаблону кнопкой `Сбросить шаблон`
- справа сайт показывает стартовый SVG или brief
- ниже он подтягивает реальные разделы и реальные файлы каталога именно под этот носитель
- блок `По брендбуку` остается deterministic и grounded, без выдуманных правил
- `Табличка` теперь умеет кабинетный, навигационный и зональный сценарии с номером, стрелкой и типом крепления
- `Презентация` собирает не только обложку, но и сценарий, площадку, ключевое сообщение и структуру слайдов
- у всех шаблонов появился единый слой оформления, привязанный к реальной структуре бренд-материалов: `CMYK для печати`, `Color`, `Black`, `White`, а также выбор `логотип с надписью / фирменный знак`
- фоновые элементы тоже стали управляемыми и grounded: можно выбрать чистый фон, сигнальную плашку, контур, водяной знак или сетку из фирменного знака вместо жёстко зашитого единственного варианта
- поверх этого слоя добавлена grounded-палитра фона для носителей на базе переданных брендовых кодов: `Фирменный красный` (`Pantone 193 C / RAL 3002 / #C40E3D`), `Мамонтовая кость` (`Pantone 7506 C / RAL 1015 / #F9F0E1`), `Ягель снежный` (`Pantone 5245 C / RAL 4009 / #F0EAED`), `Pantone 621 C` (`#E1ECE7`) и `RAL 6034` (`#D1E2E2`); эти тона работают как фоны и рамки в шаблонах
- шаблон теперь реально меняет композицию от выбранных элементов: режим `фирменный знак` перестраивает макет под знак как главный акцент, а на плотных фирменных тонах логотип/знак автоматически переходят в белую контрастную версию
- style-поля в форме больше не сухие `select`: цветовые режимы, логотип/знак, фон и палитра показываются карточками выбора с короткими пояснениями, а смена этих режимов автоматически пересобирает превью
- для `цветовой версии`, `палитры` и `элементов фона` превью теперь меняется сразу на клиенте без серого экрана и без полного блокирующего перерендера; серверная сборка при этом тихо догоняет артефакты и handoff в фоне
- поле `Город / версия` заменено на свободный `Населённый пункт`: по умолчанию ничего не выбрано, а пользователь может вписать нужный город или оставить этот блок пустым, если достаточно базового логотипа Ямала
- внутри конструктора сначала идут поля заполнения шаблона и параметры носителя, а блок `Оформление` сознательно опущен ниже, чтобы рабочий сценарий читался как `ввел данные -> посмотрел превью -> докрутил стиль`
- блок `Оформление` стал компактнее: наверху остаются только ключевые карточки выбора, а вторичные style-настройки убраны в раскрытие `Ещё настройки оформления`
- кроме палитры у конструктора появился отдельный grounded-переключатель `Дизайн`: `спокойный`, `редакционный`, `акцентный`, `плакатный`
- фоновые варианты тоже расширены: помимо `плашки`, `рамки`, `водяного знака` и `сетки` теперь есть `угловой акцент` и `мягкое пятно`
- новая палитра теперь влияет не только на swatch в UI, но и на реальные stroke/fill-слои SVG: рамки, мягкие пятна, паттерн-подложки и светлые поверхности подстраиваются под выбранный тон
- типографика в блоке `Оформление` ужата и собрана аккуратнее: карточки выбора теперь держат длинные названия и пояснения внутри плашек без наложения, а палитра фона получила более широкие и спокойные карточки без лишнего текста внутри swatch-блока
- внутри каждого носителя появились `готовые сценарии`: это быстрые grounded-пресеты вроде `официальный`, `для печати`, `контрастный знак`, `навигация`, `питч`, которые одной кнопкой меняют весь профиль шаблона
- после сборки конструктор сам раскладывает результат на два grounded-пакета handoff: `На согласование` и `Подрядчику`, чтобы визуальный показ, brief и реальные исходники не смешивались в один хвост
- рядом с превью теперь показан явный прогресс заполнения шаблона: сколько полей уже заполнено и хватает ли обязательных значений для аккуратной сборки
- там, где макет раньше показывал только знак или сырой блок без контекста, добавлены явные подписи секций вроде `Мероприятие`, `Роль`, `Сообщение`, `Следующий шаг`, `Подписант`
- SVG-превью теперь подстраивает кегль под ширину и высоту поля, чтобы длинные заголовки и подписи не вылетали за рамки макета
- общий fitter для SVG-полей теперь приоритетно сохраняет полный текст без лишних троеточий, использует безопасные внутренние отступы по ширине и высоте и аккуратно переносит сложные токены вроде дефисных фамилий
- для крупных текстовых зон в `Посте`, `Презентации`, `Сертификате`, `Бейдже`, `Табличке`, `Бланке`, `Роллапе` и `Визитке` safe-area дополнительно ужат: длинные заголовки и имена сильнее поджимаются внутри рамок шаблона
- HTML/JSON brief тоже фиксирует выбранное оформление, чтобы handoff-пакет не терял цветовую версию, тип логотипа, палитру фона, композицию и фон после выгрузки
- конструктор сам подбирает режим превью под формат носителя: широкие, квадратные, документные и вертикальные шаблоны не спорят за одно и то же окно
- кнопки `Собрать`, `Сбросить`, `Скопировать`, карточки скачивания и действия по файлам выровнены в спокойные сетки с единым кеглем
- карточки самой лаборатории упрощены: без форматных плашек и цифровых хвостов в фильтрах, только название, сценарий и кнопка входа
- формулировки на карточках сокращены до коротких рабочих summary, а текст в витрине зажат в 2 строки, чтобы сетка читалась ровно
- нижняя часть конструктора тоже уплотнена: отдельный длинный summary-блок убран, а draft показывает только компактную grounded-основу из каталога вместо трёх дублирующих колонок `Разделы / Файлы / По брендбуку`

Что выдает сейчас:
- для печатных и digital-носителей: `SVG preview + JSON brief`
- для презентации: `SVG cover + HTML brief + JSON brief`, где HTML-бриф отдельно раскладывает `Сценарий`, `Ключевое сообщение` и `Структуру слайдов`
- внутри конструктора эти артефакты и реальные файлы дополнительно раскладываются по двум сценариям:
  `На согласование` показывает визуальный пакет и ready-to-review материалы,
  `Подрядчику` держит vector/editable handoff и разделы каталога под продакшн

Что пока не делает:
- не генерирует полноценный `PPTX`
- не заменяет Figma / Canva / Illustrator
- не хранит отдельные пользовательские проекты на сервере

Прямой маршрут конструктора:
- `?view=constructor&solution=<id>`

## Ожидаемые файлы данных

По умолчанию сайт использует:
- `data/max_catalog.db`
- `data/max_bot_runtime.db`
- `data/files/`

Если `data/max_catalog.db` еще нет, сайт попробует собрать ее сам из `data/files/`.
Если в `data/files/` лежит одна верхняя папка `Макеты1`, она будет автоматически использована как корень каталога.

## Визуальные режимы

- `Витрина` - компактная главная страница с примерами, поиском и коротким входом в разделы
- `Скрыть витрину` - убирает верхний hero-блок и оставляет только рабочую область для ежедневной работы
- `Скрыть рабочую область` - убирает нижнюю рабочую сцену целиком, если нужен только презентационный экран

## Помощник

- `Помощник` открывается отдельной плавающей кнопкой и не дублирует каталог, а ведет в него
- на ПК это широкое диалоговое окно справа, на телефоне полноразмерный нижний sheet
- верхние кнопки сценариев убраны: вход в работу теперь начинается прямо с первой реплики помощника и поля ввода
- стартовые подсказки в первом сообщении строятся из `bootstrap.consultant.intents`
- подбор работает через `api.php?action=consult`
- базовая логика помощника детерминированная: разбор intent/city/format/source mode и подбор разделов/файлов идут локально
- сверху можно включить опциональный глубокий ответ через OpenAI: он добавляет отдельный блок `Глубже по задаче`, но не заменяет grounded-подбор и не должен выдумывать материалы
- помощник отдает только реальные разделы и реальные файлы, найденные через каталог и SQLite-поиск
- помощник дополнительно выделяет, что он понял в запросе: сценарий, город, формат, тип носителя, запрос на исходник
- помощник хранит короткий контекст диалога внутри панели: после `логотип Салехард` можно спросить `а для печати?` или `нужен исходник`
- ответы и стартовые подсказки живут внутри отдельной области диалога с прокруткой, а форма запроса закреплена внизу окна помощника
- при новом ответе диалог подводит начало последней реплики помощника, а не прыгает сразу в самый низ текста
- переходы по кнопкам из ответа не закрывают диалог, так что можно открыть раздел или карточку файла и тут же продолжить следующий вопрос
- на ПК диалог не схлопывается от обычных кликов по сайту; на мобильном его можно закрыть и кнопкой, и затемнённым фоном
- если LLM включен, внутри ответа появляется отдельный блок глубокого разбора: короткий вывод, 2-4 пункта, при необходимости пометка `Общая рекомендация` и следующий уточняющий вопрос
- в каждом ответе есть блок `По брендбуку`: с чего начать, какой формат брать, когда нужен исходник и какой раздел открыть следующим
- помощник отвечает и на практические вопросы применения: `можно ли на тёмном фоне`, `что отправить подрядчику`, `что показать на согласование`
- помощник отвечает и на типовые нарушения применения: `можно ли менять цвет`, `можно ли растягивать логотип`, `можно ли ставить поверх фото`
- если запрос широкий, помощник не просто возвращает шумный список, а предлагает быстрые уточнения вроде `SVG`, `PDF`, `Салехард`, `Полиграфия`
- в ответе он может:
  - предложить основной раздел
  - показать 3-4 релевантных файла
  - дать короткую брендбук-консультацию по формату, цвету, пропорциям, фону, фото, передаче подрядчику, городу, шрифтам, паттернам или носителям
  - отдать короткие уточняющие запросы для следующего шага

## Маршруты и ссылки

- главный экран и корень каталога открываются по чистому URL без параметров
- разделы используют формат `?view=folder&folder=<id>`
- поиск использует формат `?view=search&q=<запрос>`
- лаборатория решений использует формат `?view=constructor&solution=<id>`
- открытый инспектор файла добавляет `&file=<id>` к текущему экрану
- при прямом открытии такой ссылки сайт восстанавливает нужный раздел, поиск и карточку файла после загрузки
- те же ссылки можно копировать прямо из интерфейса кнопкой `Скопировать ссылку`

Inline-просмотр файлов не считается скачиванием.

## Импорт каталога по прямой ссылке

Есть отдельный GitHub Actions workflow:
- [import_regru_archive.yml](/root/projects/yamal_brand/.github/workflows/import_regru_archive.yml)

Он нужен для сценария, когда сервер недоступен по SSH, но есть прямая ссылка на архив `zip/tar/tar.gz/tar.xz`.

Что делает workflow:
- скачивает архив по `archive_url`
- делает backup текущих `data/files` и баз на хостинге
- заливает содержимое архива в `data/files/`
- удаляет старый `max_catalog.db`
- прогревает сайт, чтобы каталог пересобрался автоматически

Скрипт [import_regru_archive.sh](/root/projects/yamal_brand/scripts/import_regru_archive.sh) теперь поддерживает два режима:
- полный импорт по `ARCHIVE_URL`, когда архив содержит весь каталог `Макеты1`
- частичный sync по `ARCHIVE_PATH` + `ARCHIVE_SUBDIR`, когда нужно обновить только одну ветку внутри каталога и не трогать остальной `data/files`

Для архива `/home/sergey/yamal_brand/input/Примеры внедрения бренда территории.tar.xz` есть отдельный workflow:
- открой `Sync REG.RU Examples Archive`
- workflow берет локальный архив с self-hosted runner
- ищет внутри папку `Примеры внедрения бренда территории`
- заменяет на хостинге только эту папку внутри каталога
- удаляет `data/max_catalog.db` и проверяет, что `Хорошие примеры` и `Спорные примеры` уже читаются именно из `Примеры внедрения бренда территории/...`

## Что нужно положить на хостинг после выкладки

Минимально достаточно:
- `data/files/` с реальными файлами каталога

Дальше сайт сам:
- создаст `data/max_catalog.db`, если его нет
- создаст `data/max_bot_runtime.db`, если его нет

Можно загружать:
- либо сразу содержимое `Макеты1` в `data/files/`
- либо целиком папку `Макеты1` в `data/files/Макеты1`

Оба варианта поддерживаются.

Если позже обновишь файлы и захочешь пересобрать каталог заново, достаточно удалить `data/max_catalog.db` и открыть сайт еще раз.
