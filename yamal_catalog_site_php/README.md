# YAMAL Catalog Site PHP

PHP + SQLite версия сайта для shared hosting, в первую очередь под REG.RU.

Что умеет:
- разделы и подпапки каталога
- поиск по SQLite базе
- карточка файла
- прямое скачивание
- минималистичный интерфейс с короткими маршрутами и рабочей структурой каталога
- главный экран без дубля названия проекта: верхняя плашка объединяет знак и подпись `Официальная библиотека фирменного стиля` и остается основным акцентом hero-блока
- hero больше не отвлекает техническими счётчиками файлов и папок, верхний экран оставлен только для навигации, поиска и примеров
- в hero добавлена листаемая галерея `Примеры внедрения бренда` с вкладками `Хорошие примеры` и `Спорные примеры`
- hero-галерея примеров вынесена в левую колонку и получила миниатюры, автолистание и крупный медиа-кадр с быстрым переключением
- встроенные бренд-ассеты из каталога `Брендбук ЯМАЛ Мастер бренд`: основной логотип и фирменный знак в SVG
- верхняя навигация теперь строится из всех корневых разделов каталога, включая шрифты, брендбуки, логотипы, города, паттерны и сувенирную продукцию
- верхняя навигация по разделам собрана как одна кнопка `Открыть разделы`, после которой раскрывается компактный перечень всех разделов каталога
- внутри раскрытия `Главное меню` больше не тянется длинной вертикальной сценой: на ПК это плотная сетка, на мобильном аккуратный список
- у плиток главного меню есть активное состояние после открытия раздела
- верхний экран упрощен до двух сценариев: выбрать раздел в главном меню или сразу перейти в поиск
- мобильный первый экран перестроен в более логичный порядок: сначала основной вход и поиск, затем примеры, быстрые действия и чипы поиска собраны в компактные сетки без длинной колонны
- для ПК у витрины примеров остались явные стрелки и быстрые миниатюры, чтобы переключение не зависело только от вертикального скролла
- автолистание примеров и раскрытие разделов двигают только свои внутренние ряды и больше не должны дёргать страницу вверх
- нижняя рабочая область больше не показывает отдельный root-каталог и полностью скрыта на старте: она появляется только после выбора раздела, поиска или deep link
- отдельный режим `Скрыть витрину`, который оставляет только рабочую область
- нижняя рабочая область собрана как единая сцена: центральный раздел и выезжающий инспектор файла без отдельного левого рейла
- карточка файла в инспекторе показывает превью для изображений/PDF/SVG, компактные плашки формата/размера/даты, быстрые действия и отдельные смысловые блоки для раздела, оригинального имени и полного пути файла
- десктопный инспектор раскрывается шире, а список файлов использует ту же текстовую иерархию, что и открытая карточка: тип, чистый заголовок, контекст и отдельные плашки формата
- действия в карточке файла выровнены в ровную сетку одинаковых кнопок, а скроллбар инспектора оформлен явно и больше не выглядит как лишний прозрачный элемент
- у карточки файла собственный контейнер действий без наследования от списка, поэтому кнопки `Открыть / Скопировать ссылку / Скачать / К разделу` теперь имеют одну визуальную систему
- правая полоса прокрутки инспектора скрыта визуально, чтобы в карточке не оставался мусорный вертикальный след на ПК
- десктопный инспектор получил ещё немного ширины и более плотные внутренние отступы, чтобы плашки и кнопки не упирались в правый край
- мобильная рабочая область тоже упрощена: шапка каталога компактнее, toolbar собран в короткую сетку, breadcrumbs листаются горизонтально, а действия файлов в списке не растягивают экран вниз
- нажатие маршрутов и быстрых переходов автоматически прокручивает страницу к каталогу
- состояние раздела, поиска и открытого файла сохраняется в URL, поэтому страницу можно обновлять, отправлять ссылку коллегам и использовать `Назад / Вперед` в браузере без потери контекста
- сворачиваемая рабочая область, чтобы нижний рабочий блок можно было убрать с экрана
- рабочая область по умолчанию полностью скрыта на каждом новом заходе, а при переходе в раздел, поиск или deep link появляется автоматически
- стартовый экран не запоминает между перезагрузками состояния `Скрыть витрину` и раскрытой рабочей области
- понятный экран даже если база и файлы еще не загружены
- автосборка `max_catalog.db` из `data/files/`, если база еще не создана
- автоматическое обновление CSS/JS/SVG через версионирование ассетов, чтобы браузер не держал старый кэш после деплоя

## Примеры внедрения бренда

Hero-галерея собирается автоматически из каталога:
- если в каталоге есть папка `Примеры внедрения бренда территории`, сайт берет материалы в первую очередь оттуда
- внутри нее приоритетные подпапки:
  - `Хорошие примеры`
  - `Спорные примеры`
- `Хорошие примеры`:
  - сначала ищутся изображения строго в `Примеры внедрения бренда территории/Хорошие примеры`
  - если рядом есть более общая ветка `Примеры внедрения бренда/...`, приоритет всё равно остается за папкой `...территории/...`
  - если таких папок нет, сайт берет реальные кейсы из путей вида `.../Файлы/Макеты/...`
- `Спорные примеры`:
  - сначала ищутся изображения строго в `Примеры внедрения бренда территории/Спорные примеры`
  - если рядом есть более общая ветка `Примеры внедрения бренда/...`, приоритет всё равно остается за папкой `...территории/...`
  - если такой папки нет, ищутся изображения в папках со словами `Спорные`, `Антипример`, `Обсуждение`
  - если таких папок нет, вкладка остается пустой и показывает подсказку

Поддерживаются изображения `PNG`, `JPG`, `JPEG`, `WebP`.
В самом hero-блоке можно:
- переключать вкладки `Хорошие` / `Спорные`
- листать примеры стрелками
- кликать по миниатюрам
- включать и останавливать автолистание
- листать миниатюры влево-вправо

## Структура

- `index.php` - главная страница
- `api.php` - JSON API для фронтенда
- `download.php` - скачивание файла по `id`
- `src/site_lib.php` - вся backend-логика
- `assets/` - фронтенд
- `data/` - место для баз и файлов каталога

## Ожидаемые файлы данных

По умолчанию сайт использует:
- `data/max_catalog.db`
- `data/max_bot_runtime.db`
- `data/files/`

Если `data/max_catalog.db` еще нет, сайт попробует собрать ее сам из `data/files/`.
Если в `data/files/` лежит одна верхняя папка `Макеты1`, она будет автоматически использована как корень каталога.
Если файлов еще нет, сайт все равно откроется и покажет статус подготовки.

## Визуальные режимы

- `Витрина` - компактная главная страница с примерами, поиском и коротким входом в разделы
- `Скрыть витрину` - убирает верхний hero-блок и оставляет только рабочую область для ежедневной работы
- `Скрыть рабочую область` - убирает нижнюю рабочую сцену целиком, если нужен только презентационный экран
- `Инспектор файла` - открывается поверх каталога по клику на файл, закрывается кнопкой, по фону или клавишей `Esc`
- кнопка `Скопировать ссылку` в рабочем toolbar и в карточке файла копирует текущий deep link раздела, поиска или инспектора

## Маршруты и ссылки

- главный экран и корень каталога открываются по чистому URL без параметров
- разделы используют формат `?view=folder&folder=<id>`
- поиск использует формат `?view=search&q=<запрос>`
- открытый инспектор файла добавляет `&file=<id>` к текущему экрану
- при прямом открытии такой ссылки сайт восстанавливает нужный раздел, поиск и карточку файла после загрузки
- те же ссылки можно копировать прямо из интерфейса кнопкой `Скопировать ссылку`

Inline-просмотр файлов не считается скачиванием.

## Импорт каталога по прямой ссылке

Есть отдельный GitHub Actions workflow:
- [import_regru_archive.yml](/root/projects/yamal_brand/.github/workflows/import_regru_archive.yml)

Он нужен для сценария, когда сервер недоступен по SSH, но есть прямая ссылка на архив `zip/tar/tar.gz/tar.xz`.

Что делает workflow:
- скачивает архив по `archive_url`
- делает backup текущих `data/files` и баз на хостинге
- заливает содержимое архива в `data/files/`
- удаляет старый `max_catalog.db`
- прогревает сайт, чтобы каталог пересобрался автоматически

Скрипт [import_regru_archive.sh](/root/projects/yamal_brand/scripts/import_regru_archive.sh) теперь поддерживает два режима:
- полный импорт по `ARCHIVE_URL`, когда архив содержит весь каталог `Макеты1`
- частичный sync по `ARCHIVE_PATH` + `ARCHIVE_SUBDIR`, когда нужно обновить только одну ветку внутри каталога и не трогать остальной `data/files`

Для архива `/home/sergey/yamal_brand/input/Примеры внедрения бренда территории.tar.xz` есть отдельный workflow:
- открой `Sync REG.RU Examples Archive`
- workflow берет локальный архив с self-hosted runner
- ищет внутри папку `Примеры внедрения бренда территории`
- заменяет на хостинге только эту папку внутри каталога
- удаляет `data/max_catalog.db` и проверяет, что `Хорошие примеры` и `Спорные примеры` уже читаются именно из `Примеры внедрения бренда территории/...`

## Что нужно положить на хостинг после выкладки

Минимально достаточно:
- `data/files/` с реальными файлами каталога

Дальше сайт сам:
- создаст `data/max_catalog.db`, если его нет
- создаст `data/max_bot_runtime.db`, если его нет

Можно загружать:
- либо сразу содержимое `Макеты1` в `data/files/`
- либо целиком папку `Макеты1` в `data/files/Макеты1`

Оба варианта поддерживаются.

Если позже обновишь файлы и захочешь пересобрать каталог заново, достаточно удалить `data/max_catalog.db` и открыть сайт еще раз.
